# 教育与既有工作区的关系

决策日期：2026-09-13。采用同一产品内的独立教育领域：学习体验独立、底层服务共享、数据按用途隔离。现阶段继续使用现有应用与服务模块，不另建一套模型服务或微服务集群。

## 职责与联动

| 领域 | 自己负责 | 与教育联动方式 | 本次状态 |
| --- | --- | --- | --- |
| 教育 | 课程、先修关系、诊断、补学、练习、迁移验收、学习记录 | 编排完整学习过程，其他工作区提供能力与证据 | RAG 路径已实现诊断、实验、补救、迁移选择题验收 |
| 模型与对话 | 已配置模型、路由与调用 | 教育提供本次问题和证据，模型生成回答或导师建议 | 复用 call_routing_llm；本路径不传入可调用工具 |
| 文件与文档 | 解析、OCR、页码和原文定位、编辑及导出 | 教育引用解析结果及版本，用于教材与论文导读 | 材料工作区已复用 extract_text 导入 PDF/DOCX/TXT/Markdown，保留版本、片段与页码，不自动入正式知识库 |
| 知识库 | 资料索引、检索、来源与版本 | 教育使用指定课程资料范围，保持引用可追溯 | 实验采用独立字符检索教学基线；尚未接生产 embedding/rerank |
| 代码工作区 | 项目文件、执行、测试及产物 | 携带学习运行上下文进入项目，后续将真实执行证据回传教育 | 材料项目复用 CodingWorkflowService 执行固定 Python 教学程序，TaskRun 保存测试结果与产物摘要；可导出并往返代码工作区 |
| 3D 知识图谱 | 教育内部的先修关系与学习导航 | 节点指向课程、证据及补学路径 | 保留现有工作室图谱；本次不改渲染器 |

教育是业务领域，不是所有工作区的替代入口。用户在学习流程中调用底层能力；进入专业工作区后可以带着同一任务继续操作，并回到学习结果。

## 数据边界

- 复用 MemoryStore 的连接机制，RAG 教学事件写入独立 academy_rag_events 表，按 learner_id 查询。当前 local-user 是单用户默认值；这不是多租户鉴权，不能据此宣称已支持安全的多用户部署。
- 合成资料、诊断和导师问答不会自动加入正式知识库。用户教材通过明确导入操作进入独立学习材料表，保留源文档 ID、版本与定位信息；正式知识索引仍未联通。
- 模型回复、页面点击、下载和代码工具成功均不自动修改掌握度。固定教学检查与迁移选择题只形成有限范围的验收记录。
- 学习验收绑定运行 ID 与内容摘要。材料项目记录真实执行结果，但固定检索程序通过不证明独立编程能力，不能把下载项目包当作项目已执行。
- 合成 RAG 包只含合成资料。材料项目导出包包含学习者明确导入的解析正文、测试输入、教学脚本、报告和说明；不会包含其他个人文档、tools、模型权重、凭据或运行数据库。导出时复核代码、输入和报告摘要。

## 后续开发顺序

1. 已有教材/论文来源桥接；下一步扩展跨章节概念关联、复杂公式和表格阅读质量，完善章节级而非片段级导读。
2. 已有固定教材检索项目的真实执行与证据回传；下一步将受控的学生代码修改接入成熟沙箱与独立测试，当前入口不执行任意上传代码。
3. 已有双次模型语义评价和原句证据门槛，分歧进入待复核；仍需更大独立标注集及教师校准，四个合成回答不能证明通用评分准确率。
4. 扩展更多完整课程路径与长期复习。当前复习日期是记录与展示，没有后台提醒调度。

现有模型、文件、知识库和执行服务是统一基础设施；新增教育需求应优先扩展这些服务的结构化输出，再由教育领域编排，不复制其核心实现。
