## 修复的实际链路问题

1. MTClaw 无时间精确匹配时会回退获取旧 trace，可能误认历史/并发请求。现使用 `request_id + session_key`，没有当前证据即明确标记，缺失工具结果不能显示成功。
2. ClawOS 送来的 MemoryOS 和历史在工具路由阶段被裁成最后一条用户消息。现转交有边界的调用方背景，跳过原始工具消息和可执行调用。
3. 路由器默认内置 `ls/cat` 可截获 ClawOS 受限 wrapper。生成配置现在关闭内置工具，模型只可执行配置的受限工具；独立 MTClaw 默认行为保留。
4. 真正执行工具后，回答模型没有收到执行结果。现把有长度限制的真实观测作为 JSON 数据转交，保留原请求；不转交未经验证的路由器正文。
5. 健康端口能响应不代表可工作；模型 401 原先也被当成健康。现模型必须 HTTP 200，`/ready` 还要求工具和热身。Linux 启动门禁使用 `/ready`，并保留父进程退出清理。
6. 飞书真实消息的发送者位置、富文本二维结构、已解析列表、审批表单控件及原生审批人判定存在缺口。现已修复；租户资源隔离、实时审批重读、冻结摘要、目标撤销与并发一次分发均有回归。
7. 音频识别结果原先自动成为知识且工作流显示通过。现生成 `needs_review / waiting_gate` 草稿，保留未知说话人；复核才发布知识，原文或责任期限变化使旧知识失效。仅进度变化不使已核对的原文失效，也不向知识中写入会过期的进度值。
8. SQLite 等待和较重的文档操作可能阻塞异步 HTTP 循环。身份查询、文档、协作、数据处理、会议和音频路径采用工作线程；文档授权检查、CAS 更新、历史与审计在同一事务中。

## 权限与数据边界

- 身份由服务端签发，Cookie 为 HttpOnly/SameSite Strict，持久化仅存令牌摘要；Bearer 与 Cookie 都可注销。邀请码单次、24 小时，会话 7 天。前端 `learner_id/user_id` 不授予权限。
- 仅无身份头、无会话 Cookie、无转发头的直接回环请求可作为本机所有者。远程必须加入邀请；邀请只授予文档，不授予连接器、模型、数据库或数据/会议工作台。代理部署须保留来源信息，HTTPS 保护远程会话；没有 SSO/组织级管理员。
- 保存使用版本检查，4 秒协作状态轮询；干净文档可同步更新，脏草稿保留并提示合并。权限或身份改变会更新编辑态。撤销立即阻断后续服务端访问。评论绑定真实内容块及版本，老版本评论明确提示对照历史。
- 原有个人设备草稿迁移仅向本机所有者恢复；不同协作身份的草稿键隔离。文档保留最近 50 个实际快照。已下载的副本不能通过撤销远程删除。
- 飞书面板只报告配置就绪，不声称平台 scope 已授权。文档/会议到飞书是本地草稿；未实际创建真实租户审批或发送消息。未实现飞书云文档 ACL/双向同步。
- CSV/TSV 支持 UTF-8/BOM/GB18030；XLSX 仅第一张表，公式不执行并提示。限制 15 MB 原文件、40 MB 解压 XLSX、20,000 行、100 列、20 步处理。
- 流程始终从不可变原始来源重放，数值失败/无效流程整体回滚，过期版本返回冲突。包含去空格、数值转换、常量/均值/中位数填空、去重、条件筛选、四则派生、分组聚合和排序。
- 预览前 100 行，统计/图表计算/表格导出使用全部结果。相关仅表示线性关系；排除空值/非数值并显示数量，散点最多绘制 2,000 点，分类图最多 100 组。IQR 异常提示不自动删除，排序空值始终最后。
- 导出对 CSV/XLSX 中公式/DDE 开头文本加转义；XLSX 含来源摘要、版本和流程元数据。没有任意 Python/SQL 执行，也没有百万行计算、跨表关联或统计建模。
