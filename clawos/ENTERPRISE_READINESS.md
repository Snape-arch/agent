# ClawOS 企业级交付成熟度评估

评估日期：2026-06-13

## 结论

ClawOS 当前属于“可运行的单用户竞赛原型”，具备模型调用、工具路由、长期记忆、
反思、技能固化和可视化工作台的基础闭环，但尚未达到企业级或工业级可交付标准。

当前综合成熟度约为 38/100。完成可靠 Demo 和比赛展示没有问题；若以企业交付为
目标，必须优先补齐真实 MTClaw 集成、任务运行时、安全隔离、数据治理、可观测性、
场景工作流和可复现基准。

## MemoryOS 交付差距

已经具备：

- Profile、Preference、Project、Experience、Skill 五类统一记忆
- SQLite 持久化、关键词、BM25、轻量向量检索
- 会话记忆注入、启用和禁用、来源与置信度
- Reflection 经验写入和实时向量刷新

下一步必须实现：

1. 记忆版本表：保存旧值、变更人、变更原因和时间。
2. 冲突检测：新旧偏好矛盾时进入 Review Inbox，不直接覆盖。
3. 证据链：每条记忆关联会话、文档、工具轨迹或用户确认。
4. 生命周期：临时、长期、过期、归档、遗忘和硬删除策略。
5. 多租户边界：`user_id`、`workspace_id`、ACL 和数据隔离。
6. 安全：敏感字段加密、日志脱敏、导入导出和数据删除证明。
7. 检索评测：Recall@K、MRR、上下文命中率、错误记忆率和时延。
8. 嵌入适配：开发期可用轻量索引，交付期切换 BGE-M3/本地向量模型。

MemoryOS 验收标准：

- 1000 条混合记忆下 P95 检索时延小于 200ms。
- 标准问集 Recall@5 不低于 85%。
- 冲突记忆不得静默覆盖，所有变更可追溯和回滚。
- 禁用或删除的记忆不进入模型上下文。

## Reflection Engine 交付差距

已经具备：

- 工具轨迹采集、成功和失败判断
- 规则分析与模型分析
- 经验写入和技能使用统计
- 自动触发和手动触发

下一步必须实现：

1. 独立 `reflection_cards` 表，保存完整结构而非从 Experience 重建。
2. 用户反馈模型：满意、不满意、纠正内容和原因。
3. 改进动作状态机：建议、待审核、试运行、验证、发布、回滚。
4. 前后效果评估：同一任务重放并比较成功率、耗时、成本和质量。
5. 反思去重与聚类，避免重复经验污染记忆。
6. 失败分类体系：模型、工具、权限、参数、环境、规划和用户取消。
7. 反思质量基准，防止模型生成空泛建议。

Reflection 验收标准：

- 每次失败均产生包含证据的根因分类。
- 改进项只有通过回归任务后才可进入生产策略。
- 所有策略变化支持版本化和一键回滚。

## MTClaw 与运行时

ClawOS 已通过独立 Adapter 调用 MTClaw Function Router，不修改上游源码，并通过
session header、Tool History 和持久化 Trace 提供证据。当前剩余风险是尚未在最终
MTT AIBOOK 环境完成真实模型和性能验收。

建议建立明确适配层：

```text
ClawOS API
  -> Task Orchestrator
  -> MTClaw Adapter
  -> MTClaw Function Router / Session Bridge
  -> Tool Worker
  -> Reflection + Memory event consumers
```

验收时必须能提供：

- ClawOS 调用 MTClaw API 的代码证据。
- 一个任务从 MTClaw 路由到本地工具的完整 Trace。
- MTClaw 不可用时的降级策略。
- 与原始 MTClaw 的兼容性测试。

## 个人工作台场景扩展

### 会议与办公

当前只有会议模板、笔记和待办。交付版本需要：

- 音频导入和本地 Whisper 转写
- 说话人区分、议题、决策、风险和行动项抽取
- 行动项负责人、截止日期、提醒和状态同步
- Outlook/企业微信/钉钉/飞书日历与邮件适配器
- Word、Excel、PPT、PDF 生成和企业模板
- 会前材料、会中记录、会后跟进完整工作流

### 科研工作

- PDF/Word/网页导入、OCR、分块、引用定位
- 论文对比矩阵、方法和实验抽取
- BibTeX、GB/T 7714 和引用校验
- 文献知识库、研究问题、实验记录和结果追踪
- 可复现 Notebook、数据分析和图表生成
- 明确区分原文证据、模型总结和用户笔记

### 学习与个人成长

- 学习目标、课程计划、每日任务和复盘
- 闪卡、测验、错题本和间隔重复
- 学习资料知识库和知识点依赖图
- 学习时间、掌握度和计划偏差仪表盘
- 只允许基于学习证据更新“已掌握”状态

### 个人知识库

- 文件夹监控、批量导入、去重和增量索引
- 标签、实体、关系、时间线和双向链接
- 来源权限、引用跳转和原文预览
- 知识冲突、过期提醒和人工确认
- Markdown/Notion/Obsidian 导入导出

### 代码协作

- Git 状态、Diff、分支、提交和合并请求工作流
- 代码搜索、依赖分析、测试生成和测试执行
- Review finding、严重级别、文件行号和修复验证
- Issue、PR、CI 和发布说明适配器
- 命令白名单、隔离工作区和变更确认
- 对写操作提供 dry-run、补丁预览和回滚点

### 本地项目搭建

- 可版本化项目模板和参数表单
- Python、Node、Java、数据分析、科研和竞赛模板
- 依赖安装、环境检测、健康检查和启动验证
- Git 初始化、CI、Docker、文档和测试骨架
- 创建失败时自动补偿，不留下半成品目录

## 企业级基础能力

P0 必须具备：

- 用户、工作区、角色和权限
- 密钥管理与日志脱敏
- 工具沙箱、路径白名单和命令策略
- 持久化任务、幂等键、重试、取消、恢复和超时
- Trace ID、结构化日志、指标、告警和审计事件
- 数据迁移、备份恢复、健康检查和故障诊断
- API 版本、错误码、OpenAPI 合同和兼容性测试

P1 应具备：

- WebSocket/SSE 实时任务状态
- Worker 隔离和任务队列
- 模型路由、限流、成本预算和熔断
- 插件签名、版本、权限清单和供应链校验
- Windows 与目标 Linux/MTT 环境安装包

## 推荐实施顺序

### Sprint 1：真实运行时与安全底座

- 实现 MTClaw Adapter 和真实调用链。
- 引入持久化 Task/Step/Event 数据模型。
- 限制文件、Shell、网络工具的权限边界。
- 完成配置校验、密钥管理、Trace 和审计。
- 建立四大场景基准和真实 DeepSeek smoke test。

### Sprint 2：MemoryOS 2.0

- 版本、冲突、证据、Review Inbox 和删除流程。
- 文档导入与本地嵌入模型。
- 记忆检索评测与前端管理界面。

### Sprint 3：Reflection 2.0 与 Policy Optimizer

- 完整反思卡和用户反馈。
- 改进项状态机、回归验证和回滚。
- 上下文 Bandit 策略候选、Reward 和离线评测。

### Sprint 4-5：场景工作台

- 会议全流程、科研知识库、学习系统。
- Git 代码协作和项目模板中心。
- 文件上传、任务图、通知和实时执行界面。

### Sprint 6：本地模型与交付

- Qwen + vLLM-MUSA 部署和兼容测试。
- DeepSeek 与本地模型同一基准对比。
- 安装包、升级、备份恢复、负载和安全验收。

## 最终交付门槛

只有同时满足以下条件，才应称为企业级可交付：

- MTClaw 真实集成有代码、Trace 和测试证据。
- 核心任务成功率、延迟和资源消耗有可复现报告。
- 所有高风险工具受权限控制并可审计。
- 任务可取消、重试、恢复，写操作可预览和回滚。
- Memory 和 Reflection 的每次变更均可追溯。
- DeepSeek 与离线模型均通过同一套验收任务。
- 安装、升级、备份、恢复和故障诊断文档完整。
