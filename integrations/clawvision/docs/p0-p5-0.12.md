# P0–P5 闭环 · 0.12.0

## P0 · 可编辑 GLB/GLTF

GLB/GLTF 导入后解析为节点、Mesh、Primitive、PBR 材质、Transform 与边界。`model_scenes` 保存源资产和当前资产，`model_scene_versions` 保存每一版操作栈、场景清单和质量报告。编辑始终从不可变 Raw 资产重放，确认才创建 Release 资产。

## P1 · 自然语言编辑

中文/英文命令先解析为节点选择和结构化操作，可一次完成移动与材质等复合动作。预览接口返回临时 GLB 和受影响节点；用户确认后才创建版本，取消不会写数据库或对象存储。

## P2 · 本地质量与修复

质量报告读取真实 GLB accessor，检查退化面、边界边、非流形边和连通分量，并标记问题节点。自动修复可去重、删除退化面与孤立碎片、补边界洞和重建法线；同时生成 50% 与 25% 面数的 LOD 资产。

## P3 · 非破坏修改器栈

支持 Mirror、Array、Boolean Union/Subtract/Intersect、Subdivision、Decimate、Remesh、Normal Repair 和 Bevel。操作可启停、排序、删除和恢复。材质覆盖保留 PBR 属性，纹理重复写入 `KHR_texture_transform`。

当前 Boolean 为交互式确定性实现：Union 合并 Primitive，Subtract/Intersect 使用 cutter 包围盒进行三角面分类。它能产生真实可导出网格，但不是面向复杂工业 CAD 的精确 B-Rep 求解器。

## P4 · 资产与版本工作台

界面展示 Raw → Edit → Release 血缘、版本操作数、质量分、节点/材质/面数差异、LOD 资产和导出入口。节点支持多选、锁定、显隐、重命名、分组、复制和删除，3D 视图支持 Transform Gizmo 与 Before/After 叠加。

## P5 · 发布验收

- 数据库迁移 v5 同时覆盖 SQLite 与 PostgreSQL 方言。
- API 集成测试覆盖导入、命令、预览、确认、修改器、恢复、修复、LOD 与导出。
- 20 次连续编辑验收要求得到 21 个版本、最终质量门通过、导出 GLB 有效且没有 queued/running Text-to-3D 任务。
- 发布命令：`npm run test:release`。

第三方 Text-to-3D API 仅用于高质量生成，不是 P0–P5 编辑、修复、版本和导出的运行依赖。
