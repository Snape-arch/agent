# P0/P1 发布基线与 Text-to-3D Provider

## 数据库升级

`schema_migrations` 记录不可重复执行的版本。当前版本：v1 基线、v2 Text-to-3D Provider 生命周期、v3 Agent 取消与超时。SQLite 和 PostgreSQL 启动时执行相同语义的增量迁移；旧数据库不会依赖完整 Schema 的 `CREATE TABLE` 偶然升级。

## 服务端凭据

浏览器不再接收或上传 API Key。在线规划器从 `CLAWVISION_<PROVIDER>_API_KEY` 读取，也可以通过 `credentialRef` 引用 `CLAWVISION_CREDENTIAL_<REF>`。任何以 `VITE_` 开头的变量都会进入浏览器包，因此禁止存放密钥。

此前在对话里公开的 DeepSeek Key 必须在 DeepSeek 控制台撤销，再把新 Key 写入 `CLAWVISION_DEEPSEEK_API_KEY`。ClawVision 不会持久化该值。

## Text-to-3D Provider

- `local-implicit`：始终可用，用于快速低清预览和离线降级。
- `trellis`、`hunyuan3d`、`triposr`：独立命令 Provider；API 服务不导入 CUDA/PyTorch。
- `external`：运营方配置的 HTTPS 或 localhost 服务。

官方能力评估：TRELLIS 同时提供文本和图像条件管线，官方建议优先走图像条件；Hunyuan3D 2 的公开应用链路以图像到高分辨率纹理资产为主；TripoSR 是单图快速重建模型。因此 Hunyuan3D/TripoSR 未上传参考图时，ClawVision 会先调用 `TEXT3D_IMAGE_PROVIDER_URL` 完成 Prompt → 参考图，再进入 3D Worker。参考：[TRELLIS](https://github.com/microsoft/TRELLIS)、[Hunyuan3D-2](https://github.com/Tencent-Hunyuan/Hunyuan3D-2)、[TripoSR](https://github.com/VAST-AI-Research/TripoSR)。

每个命令从 stdin 读取一个 JSON 对象，字段包括 `prompt`、`imageBase64`、`memoryBudgetMb`、`outputFormat`。stdout 使用 JSON Lines：

```json
{"type":"progress","progress":35,"stage":"shape-generation"}
{"type":"result","format":"obj","content":"BASE64","stats":{"model":"TRELLIS"}}
```

任务先生成并持久化预览资产，再等待 GPU 并发槽。高质量 Provider 完成后执行顶点焊接、退化面/重复面清理、面数约束、法线修复、自动 UV、纹理生成和 PBR GLB 打包，最后自动替换预览。任务支持取消、超时、显存预算、checkpoint 和服务重启恢复。

## 验收

```bash
python -m unittest discover -s tests -v
python scripts/acceptance_p0.py
pnpm run verify:plugins
pnpm run build
```

`acceptance_p0.py` 通过真实 HTTP API 连续提交 20 组 Agent + Text-to-3D 流程，验证最终 GLB，并确认数据库没有非终态任务、进程表没有残留 Worker。
