# P0–P2 implementation notes

## P0 · Real experiment ingestion

- `backend/server.py`: zero-dependency threaded HTTP service.
- SQLite tables: `runs`, `metrics`, `events`, `artifacts`.
- REST endpoints support run creation, late parameters, metric upsert, events, artifacts, finish, stop and failure.
- `GET /api/runs/:id/stream` exposes an SSE run stream.
- `sdk/clawvision`: zero-dependency Python SDK.
- `examples/train_demo.py`: real logistic-regression gradient descent over a generated dataset.

Metric writes use `(run_id, step)` as a unique key so retrying a step is idempotent.

## P1 · Artifacts

Artifacts carry `name`, `type`, `mimeType`, optional `step` and JSON content. The first supported renderers are:

- `confusion-matrix`
- `sample-predictions`
- `embedding-3d`
- `checkpoint-metadata`
- generic JSON metadata

Content is currently stored inline in SQLite and limited by the API request size. Production should move binary and large JSON content to object storage.

## P2 · Comparison

- Select or hide up to ten runs.
- Align curves by step.
- Moving-average smoothing with 1, 3 or 5-step windows.
- Parameter and final-result comparison.
- Search filtering in the run rail.
- Mixed SDK and UI-simulator runs can be compared through the same schema.
