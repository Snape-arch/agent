## 修改位置

| 要修改的行为 | 入口和约束 |
|---|---|
| HTTP 请求与响应 | 在 `clawos/api/` 的领域模块处理，使用 `application/routing.py` 注入该领域需要的服务和状态。应用级身份检查仍由主入口执行。 |
| 工具路由与对话执行 | `application/execution.py` 负责模型、策略和工具执行。服务初始化和资源关闭留在应用生命周期。 |
| 数据库写入与迁移 | 实现在 `memoryos/repositories/`，会话、锁和保存点在 `memoryos/persistence.py`。启动 DDL 和兼容升级见 `schema.sql` 与 `schema.py`。跨领域写入从同一个 `transaction()` 进入。 |
| 工作区功能 | `services/workspace/` 按领域组织。报告生成依赖科研查询和渲染器，文件权限仍通过现有安全策略。 |
| 轨迹、策略和反馈 | `services/learning/` 按轨迹、策略、反馈、校准、排序和就绪检查分开。现有训练记录及发布条件沿用原契约。 |
| 控制台交互 | 在 `static/assets/console/` 对应功能文件中修改。共享 API 客户端、DOM 工具及分域状态在 `core.js`，跨功能动作在入口连线。 |
| 可视化 HTTP 与实验 | `visualization/backend/handlers/` 管理私有传输与领域入口。计算、持久化和实验任务继续通过模块服务执行。 |

`python clawos/scripts/project.py check` 会校验维护文件行数预算、逆向依赖、控制台功能间直接导入和原有仓库布局。运行版本指纹覆盖应用装配、SQL 模式和已发布前端。桌面打包仍按 Git 跟踪清单组装。

旧 Python 调用通过兼容门面访问现有处理函数。工作区和存储服务可以逐个把调用方改到对应领域接口。验收记录 GET 从源报告计算展示结果，刷新方法负责生成摘要文件和写入运行记录。这个边界有实际数据库和文件检查覆盖。

## 当前集中点

控制台样式仍有 4,271 行，部分旧页面使用多个覆盖层。MT 路由入口 2,312 行，保留了较多上游工具协议与兼容分支。课程工作台脚本和工具执行脚本仍承担多个流程。应用生命周期依赖旧调用者可替换的全局状态，兼容层还需要逐批收窄。可视化 ASGI 继续使用私有回环兼容传输，HTTP 分派与资源隔离已有运行证据。

OpenAPI 仍会为 Vision 代理和协作交付两处多方法接口报告重复操作 ID。这些自动生成的 ID 会随方法集合的迭代顺序变化。逐项对照保留了现有路由优先级、路径、参数和模式，并单独记录这两个操作 ID 组。 [全局评估](PROJECT_ASSESSMENT.md)
