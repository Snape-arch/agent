# 可维护性评估与仓库整理

评估日期：2026-11-07。判断：原仓库可维护性中等偏弱；本轮改善了模块边界、构建和说明入口，核心逻辑仍然集中，不能据此称维护性已经很强。

## 已落实的结构调整

- 已采用的MT路由实现并入 `clawos/mtclaw/router/`，启动器、桌面包、契约测试与上游许可同步；删除不参与产品的独立上游安装/卸载、演示和重复介绍。
- Vision前端并入 `clawos/web/`，领域实现、SDK与worker并入 `clawos/visualization/`。后端导入统一限定命名空间，避免与主应用的server/security/database混淆。
- 发布构建、桌面包和真实网关仍保留协议与数据路径；源码整理不重建用户库，也不搬动模型权重。
- 增加统一开发命令及源树检查。运行版本监测覆盖新模块，并在遍历前排除依赖、数据、缓存与测试目录，避免把外部依赖或用户内容当成应用源码。
- 根README和交接文件改为当前说明；过期阶段报告、重复提取文本和旧安装器从当前源码树移除。历史验收、失败证据及第三方许可保留。原设计资料仍被交付场景引用，整理到 `docs/reference/`。

## 剩余问题

| 文件 | 当前规模 | 风险与处理方向 |
|---|---:|---|
| `clawos/clawos_server.py` | 约10006行、528个函数 | HTTP路由、生命周期及业务依赖混合；先按领域提取纯查询路由，再拆有写入和鉴权的路由 |
| `clawos/memoryos/memory_store.py` | 约5258行、211个函数 | 多领域持久化集中；按领域引入仓储边界，保持事务和迁移契约 |
| `clawos/static/assets/console.js` | 约3689行 | 状态、DOM和请求混合；先明确状态管理与API模块，不整体重写已验收交互 |
| `clawos/visualization/backend/server.py` | 约2200行、125个函数 | 协议兼容与领域HTTP处理混合；逐路由迁入ASGI层，保留既有私有网关 |

静态页面与React页面并存、部分组件仍包含兼容模式，仍有进一步统一空间。不得只重命名文件就声称这些耦合消失；也不建议一次性拆散全部核心文件，使回归无法定位。

## 测试与边界

新增开发入口不替代原隔离回归。Windows安全工具桥与POSIX独立coreutils兼容测试分开：后者在Windows明确跳过，在Linux CI实际执行；不能把平台跳过计作通过。原上游还发现包装文本清理顺序错误，修正在删除时间戳之前解析转录头，保留非重复正文；权限与ClawOS默认禁用不受限内置工具的策略未放宽。

本轮验收结果见 [仓库整理验收](../clawos/benchmarks/REPOSITORY_CONSOLIDATION_ACCEPTANCE.md)。旧前端修复基线05bfe2a的云端42255945862已经真实全部通过；本轮新提交另行检查，不复用旧轮结论。

真实模型、GPU、多设备、屏幕阅读器、真人教学效果与48小时负载仍单独验收。源码清理不清除这些缺口，也不消除原始上游URL/SHA缺失。

其余待验收事项统一记录在[接手上下文](../PROJECT_CONTEXT.md#尚未验收)。
