# 维护路线图

优先稳定已存在的产品链路，新增能力必须有来源、权限、失败与恢复证据。

1. **模块边界**：按业务逐组从 `clawos_server.py` 提取API注册与生命周期依赖；保持旧URL、身份校验和数据模型，先从纯查询路由开始。
2. **存储与前端维护**：拆分大型MemoryStore的领域仓储及事务入口；为console/academy脚本建立明确状态与组件边界。静态页面逐步迁入统一前端，避免一次性重写已验证编辑器。
3. **可视化内部传输**：逐个替换遗留HTTP兼容桥，保持私有进程边界；把ASGI领域路由与核心服务分开验证。
4. **真实验证**：补齐手机与屏幕阅读器、真实模型教学解释、教师校准和真人学习效果；在允许连续运行的环境重新做多天多人负载与故障注入。
5. **参赛与发布**：围绕一条可复现教学故事演示，保留代码、引用、模型成本与未验收项；使用当前构建生成安装器，旧二进制不随源码版本化。

已完成的目录迁移与验证见[维护性评估](MAINTAINABILITY.md)，历史完整性/撤权/模型实验记录见 `clawos/benchmarks/`。历史单次通过不直接升级为当前全平台生产承诺。
